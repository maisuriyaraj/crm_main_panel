## Summary
The shared sidebar, top bar and global search. A permission-aware, collapsible sidebar exists. Since 2026-11-23 there is also a real top bar — module switcher, breadcrumb, Create (+), notification bell, Settings, Profile and More — which collapses to four controls at phone width. Global search (⌘K) is still missing. Used by all tenant users.

## Out-of-SRS behaviour
- Sidebar includes Contacts (which has a page) and a light/dark theme toggle, neither of which is in the SRS.
- **Top bar: "Plan & usage" in the profile menu, and a Settings *menu* rather than a Settings link.** The SRS lists a Settings icon; with no `/settings` index page it opens a list of the real settings pages instead. The profile menu's "preferences" (SRS wording) is served by the sidebar's existing theme toggle, not a separate preferences page.
- **`POST /app/notifications/read-all`** (crm_backend) backs the bell's "mark all read", which SH-N3 implies but does not name.
- **Billing shows the tenant's own invoices from OrbitOps**, read only — the SRS names the sidebar entry but not its contents. See the backend spec's Decisions for the route design.
- Companies, Deals, Tasks, Growth and the five Ads Manager sub-links were **removed** from the nav on 2026-11-23: each was a real link to a route with no page, so the nav advertised modules that 404. Their `pageRoutes` entries went with them; nothing else referenced them.

## Decisions (2026-11-23): what the sidebar shows
- **One rule decides each item** (`isNavItemVisible`): show it if `/auth/me` grants its `.view` key, **or** if the key is missing only because the subscription ended. `/auth/me` already strips the keys of a module closed by plan, flag or subscription, so the permission alone covers role *and* plan.
- **A module off by plan or flag is not listed at all** — not listed-but-disabled. No amount of clicking opens it, so an entry would only mislead.
- **A module closed only by an ended subscription keeps its entry**, and its page shows the upgrade message, matching the guard: `WorkspaceGate` renders the "subscription has ended" screen for anything outside `/settings`, and `NoAccess` names the subscription rather than the member's role. Hiding the app wholesale would leave nothing to act on.
- **Billing lives at `/settings/billing` on purpose.** `WorkspaceGate`'s `OPEN_WHEN_INACTIVE` already allows everything under `/settings`, so the one page a locked-out organization needs — the invoices to settle — stays reachable when every module is shut.
- **Only modules with a page are listed.** An item added before its page exists is a link to a not-found page, which reads as a broken app rather than a feature that has not shipped.
- **The "More" menu in the 360px brief does not exist yet.** The top bar holds just the sidebar trigger and the notification bell (SH-N3 is ❌), so there is no icon row to collapse. When SH-N3 is built it has to be built narrow-first.

## Decisions (2026-11-23): the top bar
- **Analytics and Calendar are not shown.** Both are named in SH-N3, neither has a page. The sidebar session settled that a nav control which lands on a 404 is worse than no control, so they are omitted rather than linked or shown disabled. This is why SH-N3 is 🟡 and not ✅.
- **Create (+) needs the module's `.create` key, not `.view`.** A reader sees no Create entry for that module at all, instead of one that fails on submit. Unlike the sidebar, Create is never offered on the strength of an ended subscription — it is a write, and the API would refuse it.
- **Create reaches a page's own dialog through `?new=1`.** The create forms are page state (`openCreate` in the Leads and Contacts pages), unreachable from the layout. The menu links to `?new=1`; `hooks/useCreateFromUrl.ts` opens the form once and strips the param, so a refresh or a Back button doesn't reopen it. This is a deliberate behaviour change to both pages.
- **Settings is a menu, not a link.** There is no `/settings` index page, so the gear lists the settings pages the member may actually open (Team, Billing, Plan & usage, Security, Company setup), each permission-checked.
- **"Account settings" and "Security" are one entry.** They would point at the same page — `/settings/security` holds the password and MFA, and there is no separate profile page — so the profile menu says "Account settings & security" once rather than listing one destination twice.
- **Width is decided in CSS, not JavaScript.** No measuring and no resize listener, so there is no reflow on first paint and the breakpoints are readable in the markup. Below `md` the Settings gear and the profile avatar are hidden and their entries move into More; from `md` up More is hidden because nothing is left over. At 360px the bar holds the sidebar toggle, Create, the bell and More, with the breadcrumb as the only flexible item — so it gives up space first and nothing wraps or overflows.
- **The breadcrumb never links a route that doesn't exist**: `settings` and `roles` are plain text. Detail pages use the entity's own name; for the role editor that name comes from Redux the page already filled, which is cheaper than the one small call the brief allowed.
- **Mark all read is one request, not N.** `POST /app/notifications/read-all` was added in crm_backend this session; marking twenty items by looping the single-item route would have been twenty writes. The reducer stamps the list in hand rather than refetching, so the bell doesn't flicker.
- **Error states in plain words**: the bell says "Couldn't load notifications. Try again in a moment." when it has nothing to show, and if a *mark* fails while a list is already on screen the message sits above the list instead of replacing it. The module switcher says "No module found."
